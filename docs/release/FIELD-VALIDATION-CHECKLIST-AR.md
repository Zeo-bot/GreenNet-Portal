# قائمة التحقق الميداني لإصدار GreenNet v1.0.0 RC2

> النطاق: MikroTik hAP ax3، RouterOS 7.23.1، معمارية arm64.  
> لا تنفّذ أي خطوة قبل أخذ نسخة احتياطية من الراوتر ومراجعة القيم الفعلية. نفّذ مسار تثبيت واحدًا فقط: **Traditional Container** أو **RouterOS Apps**.

## 1. تحضير الراوتر

- [ ] تم حفظ RouterOS backup وملف export خارج الراوتر وتسجيل وقت إنشائهما.
- [ ] تم التأكد من أن RouterOS هو `7.23.1` وأن المعمارية `arm64`.
- [ ] تم التأكد من وجود حزمة Container ومن تفعيل Container mode.
- [ ] تم تسجيل أسماء الواجهات والجسور وعناوين IP والحاويات وmount/env lists الموجودة قبل التثبيت.
- [ ] لا يوجد تعارض مع `greennet-containers` أو `veth-greennet` أو الحاوية `greennet`.
- [ ] لا يوجد تعارض مع الشبكة `172.31.255.0/30`.
- [ ] وصول API مقيد إلى عنوان حاوية GreenNet فقط، دون توسيع الخدمة أو firewall إلى WAN.
- [ ] لم تتغير إعدادات Hotspot أو PPPoE أو User Manager أو WAN أو NAT أثناء التحضير.

## 2. تحضير USB

- [ ] وسيط USB دائم، سليم، ومثبت بالاسم `usb1`.
- [ ] توجد مساحة كافية للصورة، الاستخراج، قاعدة البيانات، الرفع، والنسخ الاحتياطية.
- [ ] تم إنشاء `usb1/greennet/{data/database,data/uploads,data/backups,tmp,root}`.
- [ ] تم التأكد أن المسارات ليست على `flash/` أو تخزين مؤقت.

## 3. التحقق من الحاوية والصورة

- [ ] SHA-256 للصورة المحلية مطابق للقيمة المعتمدة.
- [ ] الصورة `linux/arm64`.
- [ ] الاستماع الداخلي للتطبيق على المنفذ `8080`.
- [ ] مسار Traditional: نُسخت الصورة إلى `usb1/greennet/greennet-v1.0.0-rc2-arm64.tar`.
- [ ] مسار Apps: المرجع هو `ghcr.io/zeo-bot/greennet-portal-mikrotik:1.0.0-rc2` والحزمة Public.
- [ ] تم اختيار شبكة داخلية للتطبيق في RouterOS Apps، ولم تتم إضافة WAN/NAT تلقائيًا.

## 4. نشر الصورة

### Traditional Container

- [ ] تمت مراجعة `deployment-values.json` و`bootstrap.rsc` سطرًا بسطر.
- [ ] استُبدل `<SET-ONE-TIME-ADMIN-PASSWORD>` محليًا بكلمة مرور قوية ولم تُحفظ في Git أو سجل الأوامر.
- [ ] تم رفع الصورة و`bootstrap.rsc` فقط بعد المراجعة.
- [ ] تم استيراد `bootstrap.rsc` مرة واحدة فقط.
- [ ] اكتمل استخراج الصورة قبل تشغيل الحاوية.

### RouterOS Apps

- [ ] استُبدل placeholder لكلمة مرور الإدارة في نسخة YAML خاصة بالمشغّل.
- [ ] استطاع الراوتر حل DNS والوصول إلى `ghcr.io` عبر الإنترنت.
- [ ] تم رفع YAML وإضافة التطبيق من واجهة Apps.
- [ ] استُخدم عنوان UI الذي تعرضه RouterOS Apps، لا عنوان `page` المفترض، إذا اختلفا.
- [ ] أُدخلت بيانات RouterOS API داخل GreenNet بعد الإقلاع، ولم تُضمّن في YAML.

## 5. الإقلاع الأول

- [ ] الحاوية في حالة running ولا تعيد التشغيل دوريًا.
- [ ] Nginx وPHP-FPM يعملان، ولا توجد أخطاء قاتلة في log.
- [ ] صفحة `/login` متاحة على المنفذ `8080` من شبكة الإدارة المصرح بها.
- [ ] تم تسجيل الدخول بحساب الإدارة المخصص ثم حفظ/تدوير كلمة المرور وفق سياسة المشغّل.
- [ ] قاعدة SQLite قابلة للقراءة والكتابة في التخزين الدائم.
- [ ] مجلدا uploads وbackups قابلان للكتابة ويظلان بعد إعادة تشغيل الحاوية.

## 6. التحقق من Hotspot

- [ ] تم أخذ نسخة من مجلد Hotspot الحالي قبل رفع ملفات GreenNet.
- [ ] SHA-256 لملفات الحزمة مطابق لـ `SHA256SUMS.txt`.
- [ ] صفحات login/status/logout/error/redirect/alogin تُحمّل دون اعتماد خارجي.
- [ ] HTTP-CHAP يعمل، ولا تُرسل كلمة المرور كنص صريح.
- [ ] PAP اختُبر فقط إذا كان مسموحًا ضمن سياسة الموقع.
- [ ] خيار Trial يظهر ويعمل فقط عند تفعيله.
- [ ] redirect يعيد العميل إلى الوجهة الصحيحة.
- [ ] الأخطاء الشائعة تظهر برسائل عربية مفهومة.
- [ ] `subscriberPortalUrl` مضبوط بعنوان HTTPS فعلي أو بقي فارغًا لإخفاء الرابط.
- [ ] اسم مضيف بوابة المشترك مضاف إلى Walled Garden عند الحاجة قبل المصادقة.

## 7. التحقق من بوابة المشترك

- [ ] تسجيل دخول مشترك حقيقي مخصص للاختبار يعمل.
- [ ] Dashboard وPackage وUsage وRenewal وNotifications وAccount وSupport متاحة.
- [ ] بيانات الباقة والاستهلاك والحالة تتطابق مع backend المختار.
- [ ] العربية وRTL والتنقل السفلي يعملان على هاتف فعلي.
- [ ] تسجيل الخروج يمحو الجلسة ويعيد إلى صفحة الدخول.

## 8. التحقق من الإدارة والأتمتة

- [ ] Dashboard الإدارة متاح.
- [ ] فحص الراوتر read-only ينجح بعنوان Traditional المحدد أو بوابة Apps الفعلية `172.18.0.1` في شبكة RC2 الميدانية.
- [ ] لا يُستخدم `localhost` كعنوان RouterOS API.
- [ ] مزامنة المستخدمين والباقات والجلسات تعرض الراوتر والـbackend الصحيحين.
- [ ] Jobs scheduler يعمل كل `300` ثانية ولا ينشئ jobs مكررة.
- [ ] أي كتابة تشغيلية تمت فقط بعد مراجعة preview والحماية المفعلة.
- [ ] تم إنشاء نسخة GreenNet احتياطية واختبار سلامة manifest وchecksum دون إجراء restore.

## 9. التحقق من التراجع

- [ ] تم تسجيل IDs الدقيقة لكل مورد أنشأه التثبيت.
- [ ] تم إيقاف الحاوية/التطبيق قبل أي إزالة.
- [ ] يمكن إزالة موارد GreenNet الدقيقة فقط دون wildcard ودون لمس خدمات الراوتر الحالية.
- [ ] بقيت بيانات `usb1/greennet/data` محفوظة قبل إزالة الحاوية.
- [ ] خطوات استعادة RouterOS backup/export معروفة للمشغّل، ولم تُنفذ إلا عند الحاجة.
- [ ] تم تسجيل نتيجة التراجع أو قرار عدم تنفيذه في `FIELD-VALIDATION-RESULT.md`.
